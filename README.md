# SaaS Customer Health Intelligence

A descriptive, diagnostic, and predictive analysis of SaaS revenue and retention metrics — built as a portfolio project to demonstrate end-to-end product analytics: data simulation, EDA, modelling, model honesty, and shipped artefacts (interactive dashboard, executable notebook, PDF report).

---

## TL;DR

- **Data:** 1,800 synthetic SaaS customers across 24 months of MRR and usage history, generated to mirror the schema of real published SaaS-churn datasets.
- **Real-world anchor:** benchmarked against Datadog and HubSpot ARR / NRR figures pulled from SEC 8-K filings and investor materials (June 2026).
- **Models:** logistic regression for churn (AUC 0.79) and XGBoost for expansion (AUC 0.78), reported side by side without cherry-picking; multi-class XGBoost for a combined customer health score.
- **Deliverables:** executable Jupyter notebook, interactive HTML dashboard (Chart.js, drill-through to customer-level), 6-page PDF insights report.

---

## Why this project

Most SaaS analytics portfolio projects stop at a Kaggle churn dataset and a single logistic regression. This one is built around three credibility moves that are typically skipped:

1. **Layered analysis** — descriptive → diagnostic → predictive in sequence, not just one of the three.
2. **Real-world anchoring** — public-company benchmark figures from SEC filings sit alongside the synthetic results, so the analysis isn't floating in a vacuum.
3. **Model honesty** — comparable AUCs across logistic regression and XGBoost are reported as observed, and the most influential coefficient (`tenure_months`) is flagged for a methodological leakage concern rather than buried.

## Dataset

### Generation

The dataset is generated by `data/generate_data.py` using a custom stochastic simulation:

- **1,800 customers** spread across three plan tiers (Starter 45%, Growth 35%, Enterprise 20%) with tier-appropriate MRR ranges.
- **24 months** of monthly MRR, login, support-ticket, and NPS history per customer, with realistic staggered signup dates.
- **Behavioural dynamics:** monthly churn probability depends on plan tier, CSM coverage, acquisition channel, tenure, usage level, and support-ticket volume. Expansion and contraction events fire stochastically each month with probabilities driven by usage and tenure.
- **Schema match:** features (`tenure_months`, `mrr`, `logins_per_month`, `active_seats_pct`, `features_adopted`, `support_tickets`, `nps_score`, `plan_tier`, `industry`, `region`, `acquisition_channel`, `has_csm`) deliberately mirror those found in published SaaS-churn datasets so the modelling code is directly portable.

### Why synthetic

Customer-level ARR / NRR data isn't publicly available — companies disclose aggregate figures in 10-Ks, not row-level customer data. Choices were:

- **Real aggregate, no modelling:** 12–40 quarterly data points across one or two companies. Not enough for a customer-level model.
- **Kaggle churn dataset:** real and citable, but the analysis sandbox couldn't reach kaggle.com.
- **Synthetic with real benchmarks:** what's built here. The customer-level modelling runs on simulated-but-realistic data; the benchmark layer (Section 04 of the dashboard) uses actual reported figures from Datadog and HubSpot.

Every artefact labels the data as synthetic. None of it is passed off as real.

## Analysis layers

### 01. Descriptive

- ARR trajectory across the 24-month window.
- Trailing-twelve-month NRR series, cohort-based: for each month *m*, NRR is computed as the active-cohort's MRR at *m* divided by that same cohort's MRR at *m − 12*. Customers who joined within the trailing window are excluded from the denominator (otherwise NRR inflates artificially).
- Churn rate decomposition by plan tier, region, and acquisition channel.

### 02. Diagnostic

Two models, run on the same train/test split:

| Model | Target | AUC | Purpose |
|---|---|---|---|
| Logistic Regression (class-weight balanced) | `churned` | 0.79 | Interpretable coefficients for churn drivers |
| XGBoost (n=150, depth=4) | `expanded` | 0.78 | Non-linear interaction effects for expansion |

Standardised logistic coefficients are visualised in the dashboard's driver chart. SHAP summary plots accompany the XGBoost expansion model in the notebook.

**Honest reporting:** the two AUCs are comparable, which indicates the underlying signal in this synthetic dataset is largely linear and additive. That's a useful finding, not a weakness to hide.

### 03. Predictive

A multi-class XGBoost classifier (`objective="multi:softprob"`, 3 classes) produces a combined customer health label:

- **0 — Churned:** customer is no longer active.
- **1 — Stable / At-risk:** active but neither expanding nor contracting much.
- **2 — Healthy / Expanding:** active and net-positive MRR change.

Predicted probabilities are converted to a `risk_score_0_100` (probability of class 0 × 100) used by the dashboard's customer drill-through.

### 04. Real-world benchmark

Pulled June 2026 from:

- **Datadog** — Form 8-Ks (FY2025 and FY2026 quarterly), investor materials. Consumption-based pricing, ARR ~$4.23B, NRR 110–130% range.
- **HubSpot** — Form 8-Ks (FY2025 and FY2026 quarterly), Q1 2026 earnings transcript. Seat/tier-based pricing, ARR ~$3.7B equivalent, NRR ~103% in Q1 2026.

HubSpot is the structurally comparable benchmark for the synthetic book; Datadog is the aspirational upper bound that requires a pricing-model change, not just retention discipline.

## Methodology caveats

These are surfaced both in the dashboard's "Methodology & Caveats" tab and here, because credibility-over-flattery is one of this project's working principles.

1. **`tenure_months` as a churn predictor is partly downstream of the outcome.** A customer who churned in month 4 has `tenure_months = 4` regardless of behaviour. A production-grade churn model should use snapshot features at month *T* to predict churn over months *T+1 ... T+k*, not point-in-time tenure of an already-resolved customer. Reported here as observed; would be re-built for a real production setting.

2. **Synthetic data has built-in correlations.** The simulation generates churn and expansion using business-driven rules (usage, tenure, CSM coverage) plus probabilistic noise. The diagnostic findings are real for *this dataset* but reflect the simulation's structure as much as any external truth. The real-world benchmark layer exists precisely to anchor against this.

3. **Stable / At-risk middle class is a residual.** It's defined as "active but neither expanded nor contracted much," which is a catch-all. Most of the predictive model's classification error is concentrated there — expected and disclosed in the confusion matrix.

4. **Single train/test split, no cross-validation.** A production model would cross-validate, calibrate, and report decision-curve analysis alongside AUC. The portfolio focus here is the end-to-end story, not maximum-rigour modelling.

## How to run

```bash
# 1. Generate the dataset
cd data && python3 generate_data.py

# 2. Build and execute the notebook
cd ../notebook
python3 build_notebook.py
jupyter nbconvert --to notebook --execute --inplace product_analytics.ipynb

# 3. Build the dashboard (depends on kpis.json + scored_customers.json from step 2)
cd ../dashboard
python3 -c "import pandas as pd; pd.read_csv('scored_customers.csv').to_json('scored_customers.json', orient='records')"
python3 build_dashboard.py

# 4. Build the PDF report
cd ../report && python3 build_report.py
```

Open `dashboard/saas_health_dashboard.html` in any modern browser.

## Key findings

- **Trailing NRR sits in the 100–108% band** across the observation window — net-positive but well below the consumption-pricing benchmark range Datadog operates in.
- **Plan tier dominates churn risk:** Starter tier (47% churn) ≈ 5× Enterprise tier (9% churn), with Growth tier in between (28%).
- **CSM coverage is a measurable lever** even controlling for other features — the standardised coefficient for `has_csm` is meaningfully negative in the logistic regression.
- **Acquisition channel matters more than region.** Region distribution is nearly flat; Product-Led-Trial customers churn at the highest rate.
- **The gap to the HubSpot benchmark (~103% NRR) is the actionable comparison.** Closing it is a CSM / product-adoption story, not a pricing change. Closing the gap to Datadog requires consumption pricing.
